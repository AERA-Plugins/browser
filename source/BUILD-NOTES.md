# Browser integration status

This is a **staged integration, not a working on-device web browser**. The
native Menu > Browser page and compressed WPE runtime are included in the
recovery image. Wi-Fi is intentionally unchanged. No browser runs at boot.

## Implemented

- Native address editor/keyboard, HTTP(S) validation, progress and error display.
  Back/forward/reload/stop remain disabled until a real isolated session exists.
- Deterministic ARM64/XZ payload; the recovery's existing LZ4 ramdisk format is
  unchanged. The payload carries WebKit, JavaScript JIT, WebAssembly, TLS,
  certificates, full ICU data, fonts, keyboard data and the software worker.
- On-demand background expansion into a private RAM directory. Compressed and
  expanded SHA-256, fixed byte/member limits, CRC32, restricted paths/modes,
  no symlink traversal, no special files and cleanup on cancellation/exit.
  The verified directory is not published until the whole stream validates.
- ARM64 `aera-browser-worker`, a WPE software-display subclass that does not
  request EGL. Bounded 720x1100 ARGB pixel bridge, one outstanding frame with
  acknowledgement, validated input, temporary network sessions and TLS failure
  enforcement. Downloads, file choosers, permissions and new windows are denied.
- Native LVGL-side nonblocking session transport, copied image buffers, required
  memfd size seals, navigation controls, touch scrolling and an ASCII keyboard.
  Closing the page closes its channel; a lost/invalid channel shows an error.
  Host tests use a synthetic channel, not an unsandboxed WebKit process.

## Remaining launch gate (not a Wi-Fi problem)

The inspected dodge kernel lacks CONFIG_USER_NS and CONFIG_PID_NS. WebKit's
stock bubblewrap isolation cannot work with that kernel. The recovery does not
launch the worker: `LaunchBlockReason()` is deliberately fail-closed even on a
host with those namespaces. Merely enabling kernel options must not bypass it.

An audited launcher must create a restricted filesystem/process environment,
drop root/capabilities/inherited descriptors and expose only the pixel/input
channel. It must own/reap the browser process tree and pass its two channels to
`BuildWebScene`, followed by end-to-end rendering/input tests. The worker compiled
successfully but has **not** been executed on the phone. Its non-root and
no-new-privileges checks are defense in depth, not a sandbox implementation.

Do not set `WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS`, run MiniBrowser as root,
or expose recovery operations to web content. Neither a marker file nor an
environment override can enable launch in this build.

## Build and tests

`Android.mk` installs the payload when the ARM64 product requests
`aera-browser-runtime`. `prebuilt/aera_browser_payload.hpp` and `runtime.xz`
are an inseparable pair generated by `pack.py`. A different archive needs a
regenerated header and recovery rebuild. The manifest is a build-time inventory,
not a runtime input.

The temporary WPE build is at `/tmp/aera-webkit/build21`; cross-build support
and limitations are recorded in `/tmp/aera-webkit/STATUS.md`. The original
runtime was measured by `/tmp/aera-webkit/package-runtime.py`.

```sh
bash bootable/recovery/ui2/browser/build-worker.sh /tmp/aera-worker
python3 bootable/recovery/ui2/browser/pack.py STAGED_RUNTIME OUTPUT_DIRECTORY
bash bootable/recovery/ui2/browser/test-runtime.sh
```

The parser/protocol tests use ASan/UBSan and real payload extraction, corruption,
truncation, cancellation and musl-loader alias checks. UI tests mock preparation
and assert that Go cannot dispatch a recovery operation.

## Distribution

Private development image only: not ready to publish. WebKit 2.52.6 is built
from the official release archive (SHA-256
`b2bafef2751625b7fdf530f230ff0f542ff0eeba3590c3a989d931b2a55c858e`).
The runtime includes third-party LGPL/BSD/MIT/font/data components, not just
AERA's Apache-2.0 code. A complete license/source bundle, portable toolchain
recipe and security-update procedure are still required before distribution.
Video/audio, WebRTC, WebGL and PDF.js are disabled; not every website is supported.
